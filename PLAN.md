# PLAN — Aadhaar-Based Medical Document Information Extraction System
### (NLP, EHR, and LSTM — college ML project)

Doctor-only Flask web app with synthetic-Aadhaar patient lookup and a genuine
LSTM information-extraction pipeline. Synthetic data only (MED-1 … MED-50);
never replace with real Aadhaar or real patient records.

## Phase 5 — LSTM Model, Training & Inference  `[done]`
Requirements (user-approved):
1. Genuine LSTM sequence model; LSTM must really participate in inference.
2. Uses Phase 4 preprocessing + the 50 synthetic documents.
3. Learn to distinguish/retrieve clinically relevant information from
   clinical-note text → **token-level information extraction (BIO tagging)**.
4. Framework must work on this Python environment — check version + installed
   packages first; do NOT force TensorFlow if no compatible wheel; PyTorch or
   NumPy-based real LSTM acceptable.
5. Correct gate semantics: forget gate = multiplicative retention control over
   previous cell state c_{t-1}; input gate = multiplicative control of new
   candidate content; output gate = control of exposed h_t. Never describe the
   forget gate as "deleting unwanted information".
6. Clearly separated code: data preparation / labels / model definition /
   training / evaluation / model saving / inference.
7. Labels: meaningful demo labels generated from the existing dataset by
   documented, deterministic rules (`labels.py` docstring + this plan).
8. Evaluated with appropriate metrics; small-synthetic-dataset limitations
   stated explicitly.
9. Saved artifacts under the project model directory (`model/`):
   weights, vocabulary copy, tag map, training config, metrics.
10. Inference loads the saved model ONCE (singleton) and reuses it; never
    retrains on lookup.
11. Unit/smoke tests: preprocessing → sequences → LSTM → prediction →
    save → reload → same prediction.
12. No changes to auth/lookup flow; no dashboard redesign.

## Global constraints (all phases)
- Synthetic data only; no real Aadhaar/patients; no secrets in frontend.
- Doctor username regex and auth semantics are frozen.
- `api.js` is the only place frontend network calls are written.
- `SampleOutput.py` must never be executed (it regenerates/overwrites the
  dataset and blocks on stdin); dataset is read-only via
  `sample_medical_documents.py`.
- Framework decision (TF wheel unavailable on this Python) resolved in
  Phase 5 by environment check.

- PyTorch 2.14.1+cpu (normal PyPI; `download.pytorch.org` unreachable) + numpy 2.5.3.
